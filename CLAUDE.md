## Commands

```bash
# Development (runs web + API worker concurrently)
npm run dev

# Web only (port 3000)
npm run dev:web

# API worker only
npm run dev:api

# Build
npm run build

# Run all checks (biome lint+format + typecheck + tests)
npm run verify

# Lint + format check
npm run check

# Type check only
npm run typecheck

# Tests (run all)
npm test

# Run a single test file
npx vitest run src/lib/geo.test.ts

# Deploy (build + deploy web + deploy API)
npm run deploy
```

The linter/formatter is **Biome** (not ESLint/Prettier). Use `npm run check` to check and `biome check --write` to auto-fix.

## Architecture

Prahra is a GPS-based city puzzle game (outdoor scavenger hunt) — a PWA deployed to Cloudflare Workers.

### Two separate Cloudflare Workers

**Web app** (`wrangler.jsonc`) — TanStack Start SSR app serving `prahra.cz/*`
- Entry: `@tanstack/react-start/server-entry`
- Uses Cloudflare D1 database binding `prahra_db`

**API worker** (`api/wrangler.api.jsonc`) — Hono REST API serving `prahra.cz/api/*`
- Entry: `api/src/index.ts`
- All `/api/*` routes require a Clerk JWT Bearer token
- D1 tables: `users`, `game_progress`, `level_progress`

### Frontend routing

TanStack Router with file-based routes under `src/routes/`:
- `/` — home, list of published games
- `/game/$gameSlug/intro` — pre-game intro screen
- `/game/$gameSlug/` — the active game engine (requires Clerk sign-in)

`src/routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin — do not edit manually.

### Game data model

Games are statically defined TypeScript objects in `src/data/games/`. Each `Game` has ordered `Level[]` entries with GPS coordinates, answer validation, hints, and point values. See `src/types/game.ts` for the full type definitions.

To add a new game: create a file in `src/data/games/` and register it in `src/data/games/index.ts`.

### Game state & progress sync

`useGameState` (`src/hooks/useGameState.ts`) manages all in-game state with localStorage persistence (key: `prahra_<slug>_state`).

Progress is synced to the API (when signed in) via:
- `useProgressLoad` — loads remote progress on mount and merges with local state
- `useProgressSync` — pushes state changes to API reactively

Merge strategy: the more advanced state wins (scored by `progressScore`), with hints and completed levels always accumulated.

### GPS unlock flow

1. `useGeolocation` tracks player position via the browser Geolocation API
2. `haversineDistance` (`src/lib/geo.ts`) calculates distance to the current level's target
3. When the player enters `level.unlockRadius` meters, `unlockLevel()` is called
4. The `PuzzleCard` becomes visible; answer is validated via `validateAnswer` (`src/lib/validate-answer.ts`)
5. On correct answer, `completeLevel()` advances to the next level

### Auth

Clerk handles auth. `VITE_CLERK_PUBLISHABLE_KEY` env var enables it in the frontend. If the key is missing, the app renders without `ClerkProvider` (useful for local dev without auth). The API worker uses `CLERK_SECRET_KEY` (set in Cloudflare worker secrets) to verify JWTs via `@clerk/backend`.

### Feature flags

`src/lib/featureFlags.ts` — currently only `debugMode`, enabled in dev when `VITE_FEATURE_DEBUG_MODE=true`. The debug panel lets you teleport to GPS coordinates during development.

### UI components

Radix UI primitives + Tailwind CSS v4 + `class-variance-authority`. Component library lives in `src/components/ui/`. Game-specific components are in `src/components/game/`.

Leaflet/react-leaflet is used for the map and is lazy-loaded (it's heavy).
